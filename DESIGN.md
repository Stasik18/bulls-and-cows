# DESIGN

## 1. Структуры данных

### GameState

`GameState` — основная структура, в которой хранится текущее состояние игры:

- `secret` — загаданное число или `null`, если игра ещё не началась.
- `length` и `base` — выбранная длина числа и система счисления.
- `history` — история всех введённых попыток и результаты их проверки.
- `startTime` и `finishTime` — время начала и окончания игры.
- `status` — состояние игры: `idle`, `playing` или `won`.
- `modalStatus` — состояние модального окна: открыто оно или закрыто.

Структура находится в `src/storage/gameState.ts`. Функция `setGameState` создаёт новый объект состояния с обновлёнными свойствами, а не изменяет существующий объект напрямую. После обновления она уведомляет все функции, зарегистрированные в `Set` `listeners`. Подписчики могут получить актуальное состояние и обновить интерфейс. Функция `subscribeGameState` добавляет подписчика и возвращает функцию для отмены подписки.

### GuessHistoryEntry

`GuessHistoryEntry` описывает одну попытку:

- `guess` — введённое число.
- `bulls` — количество цифр, которые совпали с загаданным числом и по значению, и по позиции.
- `cows` — количество цифр, которые есть в загаданном числе, но находятся на других позициях.

История хранится в массиве. Массив сохраняет порядок попыток и позволяет отображать историю игры в интерфейсе.

### LeaderboardEntry

`LeaderboardEntry` описывает одну завершённую игру. Структура хранит количество попыток, продолжительность игры, систему счисления, длину загаданного числа и временную метку завершения. Таблица лидеров хранится в `localStorage` в виде массива: перед записью он преобразуется в JSON с помощью `JSON.stringify`, а при чтении восстанавливается с помощью `JSON.parse`.

### SYSTEMS

`SYSTEMS` из `src/constants/systems.ts` содержит список поддерживаемых систем счисления. Каждый элемент описывает название системы, её основание и доступные в ней цифры. Интерфейс настроек использует эти данные для отображения систем счисления и доступных цифр. Функции валидации используют их, чтобы определить, какие символы разрешены.

### Map в countPossibleSecrets

В `src/game/countPossibleSecrets.ts` используется `Map` для мемоизации результатов. Ключ формируется из входных параметров (`length` и `base`), а значение содержит рассчитанное для этих параметров количество возможных секретных чисел. Перед выполнением рекурсивных вычислений функция проверяет, есть ли результат с такими параметрами в кэше.

## 2. Алгоритмы

### generateSecret

`generateSecret` получает необходимую длину секретного числа и основание выбранной системы счисления. Функция берёт доступные цифры для выбранной системы, перемешивает их алгоритмом Фишера — Йетса и возвращает нужное количество цифр с помощью `slice`. В качестве необязательного аргумента можно передать функцию генерации случайного числа. Это позволяет использовать предсказуемые значения во время тестирования.

Первая цифра может быть нулём. Цифры в секрете не повторяются, потому что исходный массив содержит каждую доступную цифру только один раз, а после перемешивания из него выбирается нужное количество элементов.

### evaluateGuess

`evaluateGuess` сравнивает загаданное число с введённой попыткой. Каждая цифра классифицируется как бык, корова или несовпадение:

- бык — цифра совпадает и по значению, и по позиции;
- корова — цифра есть в загаданном числе, но находится на другой позиции;
- несовпадение — такой цифры нет в попытке.

В реализации `map` создаёт массив результатов сравнения, `filter` удаляет элементы, которые не являются ни быками, ни коровами, а `reduce` подсчитывает количество быков и коров. Сравнение цифр не зависит от регистра, что особенно важно для шестнадцатеричной системы счисления.

### isValidGuess

`isValidGuess` проверяет, что попытка имеет нужную длину, не содержит повторяющихся цифр и использует только символы, доступные в выбранной системе счисления. Для проверки уникальности используется `Set`, а для проверки каждого символа — предикат, возвращаемый функцией `createDigitValidator`.

### createDigitValidator

`createDigitValidator` — функция с каррированием: сначала она получает основание системы счисления, а затем возвращает функцию, которая проверяет, разрешён ли конкретный символ в этой системе. Один и тот же валидатор можно повторно использовать при полной проверке попытки и при фильтрации пользовательского ввода в игровом интерфейсе.

### countPossibleSecrets

`countPossibleSecrets` рекурсивно вычисляет количество уникальных секретных чисел для выбранной длины и основания системы счисления. На каждом шаге количество вариантов для первой цифры умножается на количество вариантов для оставшихся позиций:

`count(length, base) = base * count(length - 1, base - 1)`

У рекурсии есть два базовых случая:

- если `length` равен `0`, существует один возможный вариант — пустая последовательность;
- если `length` больше `base`, возможных секретных чисел нет, потому что доступных уникальных цифр недостаточно.

Результат каждой подзадачи сохраняется в `Map`, поэтому повторно вычислять количество вариантов для тех же параметров не требуется.

## 3. Сложность алгоритмов Big O

В этом разделе `n` обозначает длину секретного числа, а `b` — основание системы счисления. Ограничения игры требуют, чтобы для допустимых настроек выполнялось `n <= b`.

| Функция                | Временная сложность | Пространственная сложность | Обоснование                                                                                                                                                                                                                                    |
| ---------------------- | ------------------- | -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | `O(b)`              | `O(b)`                     | Функция подготавливает и перемешивает массив доступных цифр, а затем копирует до `n` элементов с помощью `slice`. Поскольку `n <= b`, обе операции ограничены размером основания системы счисления.                                            |
| `evaluateGuess`        | `O(n²)`             | `O(n)`                     | Для каждой цифры секрета проверяется, содержится ли она в попытке. Линейная проверка наличия, повторённая для `n` цифр, даёт квадратичную временную сложность. Разбиение строк и промежуточные массивы требуют линейной дополнительной памяти. |
| `isValidGuess`         | `O(n)`              | `O(n)`                     | Функция проверяет длину, создаёт `Set` для поиска повторов и проверяет каждую цифру валидатором. `Set` и временный массив символов требуют линейной дополнительной памяти.                                                                     |
| `countPossibleSecrets` | `O(n)`              | `O(n)`                     | Мемоизация предотвращает повторное вычисление одних и тех же подзадач. Один расчёт проходит по рекурсивной цепочке длиной не более `n` шагов. Стек рекурсии и сохранённые промежуточные результаты требуют линейной памяти.                    |

## 4. Принципы Clean Code

### Разделение ответственности

Приложение разделяет сборку страниц, элементы интерфейса, пользовательские действия, игровые правила и хранение состояния:

- `src/pages/` содержит сборку страниц и связывает необходимые элементы интерфейса с действиями.
- `src/components/` содержит DOM-элементы и поведение отдельных частей интерфейса.
- `src/controllers/` обрабатывает действия пользователя и координирует изменения состояния игры.
- `src/game/` содержит игровые правила и алгоритмы: генерацию секрета, проверку попыток и расчёт результатов.
- `src/storage/` содержит состояние игры и механизм подписки на его изменения.

Например, `src/controllers/game-controller.ts` обрабатывает отправленную попытку и обновляет состояние игры, а `src/game/evaluateGuess.ts` содержит алгоритм сравнения чисел. Логике сравнения не требуется знать, каким образом отображается интерфейс.

### Выделение сложной логики

Обработчик события ввода в `src/components/game/game-panel.ts` вынесен в отдельную функцию `handleGuessInput`. Благодаря этому основная функция компонента сосредоточена на сборке игровой панели, а шаги обработки пользовательского ввода можно рассматривать отдельно.

В `src/components/home/home-panel.ts` функции `createLengthOptions`, `createDigitElements` и `createSystemOptions` создают связанные группы DOM-элементов и возвращают их в `HomePanel`. Сборка страницы остаётся внутри `HomePanel`: эти функции не создают дополнительные компоненты и не забирают на себя ответственность за всю страницу.

### DRY

Расчёт результата игры вынесен в общую функцию и используется как в модальном окне победы, так и в таблице лидеров. `src/components/modals/win-modal.ts` и `src/components/modals/leader-modal.ts` используют одну и ту же логику расчёта, поэтому формула не дублируется в двух местах.

### KISS

В `isValidGuess` для проверки условий используются методы массивов, например `every`, вместо отдельного булевого флага, который изменялся бы во время обхода массива. Так намерение проверки выражено непосредственно и читается проще.

### Понятные имена и типизированные контракты

Названия `GuessHistoryEntry`, `LeaderboardEntry`, `createDigitValidator` и `countPossibleSecrets` объясняют назначение структур данных и функций. Интерфейсы TypeScript описывают данные, которыми обмениваются части приложения, и делают их контракты явными.

### Создание DOM без вставки HTML-строк

DOM-элементы создаются через вспомогательную функцию из `src/helpers/fabric-elemnt.ts`, а не путём вставки HTML-строк с помощью `innerHTML` или `insertAdjacentHTML`.

## 5. Принципы функционального программирования

### Чистые функции

Игровые вычисления и проверки вынесены в отдельные функции, которые получают необходимые данные через параметры и возвращают результат. Примеры: `evaluateGuess`, `isValidGuess` и `countPossibleSecrets`. `generateSecret` также принимает функцию генерации случайного числа как аргумент, что позволяет контролировать случайные значения в тестах.

### Иммутабельность

Состояние игры обновляется созданием нового объекта с изменёнными свойствами, а не прямым изменением текущего объекта. Благодаря этому изменения состояния выражены явно, и подписчики могут реагировать на каждое обновление.

### Функции высшего порядка

Методы массивов `map`, `filter`, `reduce`, `every` и `some` принимают функции обратного вызова и используются для преобразования или проверки коллекций. `createDigitValidator` также возвращает функцию, которая затем используется как предикат.

### Каррирование

`createDigitValidator(base)` сначала получает основание выбранной системы счисления, а затем возвращает функцию для проверки отдельного символа. Возвращённую функцию можно использовать повторно везде, где нужно проверить допустимость цифры для этой системы.

### Рекурсия и мемоизация

`countPossibleSecrets` решает задачу рекурсивно, уменьшая оставшуюся длину числа и количество доступных цифр. Рассчитанные результаты сохраняются в `Map`, чтобы при повторном обращении к той же подзадаче можно было вернуть значение из кэша.
